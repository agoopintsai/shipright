## Question

For every part of the plan (field, switch, compatibility layer, optional UI, report, notification), ask what happens if we cut it. If nothing in the scope shrank by the end of the session, the questioning was too soft: ask again. Record what was cut so it can be added back later with a paper trail.

## Why it matters

Whatever survives deletion inherits the full safety review and a lifetime of maintenance. The cheapest code is code that does not exist. A common heuristic: if you never have to add back some of what you deleted, you did not delete enough.

## Origin

Deletion-first thinking from the "question, delete, simplify, accelerate, automate" engineering sequence.
